# GitHub Actions Data Trace

## Workflow: authority-v4-autopilot.yml

Trigger:

- Manual: `workflow_dispatch`
- Scheduled: daily cron at `22 14 * * *`

Permissions:

- `contents: write` so the workflow can commit generated pages/reports.
- `issues: write` so the workflow can open a failure issue.

Step-by-step data trace:

1. `actions/checkout@v4`
   - Input: GitHub repository contents.
   - Output: Working copy on runner.
   - No external content API call.

2. `actions/setup-python@v5`
   - Input: requested Python version `3.11`.
   - Output: Python runtime.
   - No repo data mutation.

3. `python3 scripts/authority_v4_autopilot.py`
   - Reads:
     - `content-bank/yearly-pantry.json`
     - `content-bank/scaling-policy.json`
     - `prompts/human_pov_editorial.md` only if Gemini rewrite is attempted
     - `data/autopilot-state.json` if present
     - `data/link-registry.json`
     - `data/social-queue.json`
   - Environment variables:
     - `DAILY_PAGE_LIMIT`
     - `MIN_BASE_PUBLISH_SCORE`
     - `ENABLE_GEMINI_REWRITE`
     - `GEMINI_API_KEY` optional secret
     - `GEMINI_MODEL`
     - `LINKEDIN_DAILY_LIMIT`
     - `X_DAILY_LIMIT`
     - `FOUNDER_PUBLICATION_DOMAIN`
     - `MEMPHIS_PUBLICATION_DOMAIN`
     - `PROFESSIONAL_PUBLICATION_DOMAIN`
   - Writes:
     - New generated HTML pages under `sites/*/daily/`
     - Updated `sites/*/sitemap.xml`
     - Updated `sites/*/llms.txt`
     - Updated `data/autopilot-state.json`
     - Updated `data/link-registry.json`
     - Updated `data/social-queue.json`
     - Updated `reports/v4-autopilot-report.json`
   - External calls:
     - None unless `ENABLE_GEMINI_REWRITE=true` and `GEMINI_API_KEY` exists.
   - Failure behavior:
     - Failed/low-score pages are skipped.
     - Gemini failure does not block publishing if the deterministic base page passes.

4. `python3 scripts/hostile_review.py`
   - Reads:
     - `data/brands.json`
     - `data/publications.json`
     - `data/network-rules.json`
     - `data/social-queue.json`
     - HTML pages under `sites/*`
   - Writes:
     - `reports/hostile-review-report.json`
   - Fails workflow if:
     - any external target domain is outside registry
     - publication lane links to disallowed target
     - YMYL page lacks disclaimer
     - social status is not draft-only
     - duplicate social body exists
     - banned claims appear

5. `python3 scripts/link_audit.py`
   - Reads:
     - HTML pages and registry data.
   - Writes:
     - `reports/link-audit.json`
   - Fails workflow if:
     - link direction/domain rules are violated.

6. `stefanzweifel/git-auto-commit-action@v5`
   - Commits only:
     - `sites/**`
     - `data/**`
     - `reports/**`
   - Does not commit scripts/prompts/docs on daily runs.
   - Cloudflare deploys from GitHub after commit using Cloudflare Git integration.

7. `dacbd/create-issue-action@v2`
   - Runs only on failure.
   - Opens an issue titled `Authority V4 autopilot failed`.

## Workflow: hostile-review.yml

Trigger:

- Pull request
- Push to `main`

Step-by-step data trace:

1. Checkout repo.
2. Setup Python 3.11.
3. Run hostile review.
4. Run link audit.
5. Upload `reports/` as an artifact.

No content is generated by this workflow. It is a gate and report workflow only.

PASS. The autopilot workflow has a complete read/write path, avoids direct Cloudflare deploy secrets, and leaves Cloudflare deployment to the existing Git integration.
