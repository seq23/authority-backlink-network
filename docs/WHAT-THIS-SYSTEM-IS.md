# What the Authority Network Is

## Plain-English explanation

The Authority Network is a small publishing system that runs several useful resource websites from one repository.

Its job is to:

1. create practical articles for real readers;
2. keep each publication inside its approved subject area;
3. add relevant links to approved products or resources when those links genuinely help;
4. prevent fake rankings, exaggerated claims, wrong-domain links, hidden affiliation, and accidental publishing mistakes;
5. prepare approved social posts for LinkedIn and X;
6. keep an auditable record of what was generated, linked, validated, and posted.

It is not a directory-selling scheme, a fake review network, or a machine that inserts links into every page. A page must remain useful even when the product link is removed.

## Dream Wedding Builder

Dream Wedding Builder is one multi-domain product ecosystem. It owns four domains and five product routes:

- Free Dream Wedding Builder — `/build`
- Wedding Checklist PDF — `/products/checklist-pdf`
- Wedding Budget Spreadsheet — `/products/budget-spreadsheet`
- Wedding Timeline Template — `/products/timeline-template`
- Wedding Seating Chart Maker — `/products/seating-chart-maker`

The system normally uses the domain that best matches the selected product, but it validates every approved domain/route combination.

## What runs automatically

Depending on repository and GitHub settings, automation can:

- generate a controlled number of pages;
- update sitemaps and `llms.txt` files;
- validate pages and links;
- repair safe mechanical defects once;
- queue social posts;
- publish social posts when real provider credentials are present;
- commit generated content and receipts.

## What never runs silently

The system does not invent sources, testimonials, local facts, rankings, prices, or provider credentials. It does not treat a warning about word count as a release failure. It does not keep repairing the same page in an endless loop.

## How v4.5 validation works

There is one validation controller. It calls:

- one shared page-audit engine;
- one bounded repair engine;
- one content-addressed cache;
- the existing link, safety, workflow, and social-contract checks;
- one deterministic clean-build proof.

The cache can make repeated validation faster, but it can never turn a failure into a pass. Missing or corrupt cache entries cause fresh validation.
